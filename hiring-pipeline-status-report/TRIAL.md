# Hiring pipeline status report: trial on the invented example

- **Product:** Claude, run in Claude Code
- **Model:** Claude Sonnet 5.5 (model ID claude-sonnet-5-5)
- **Date:** 2026-11-10

The inputs for this run are the invented example in `public/example.md`: its settings, list of roles, applications export of 9 November 2026, this week's blocker note and last week's blockers. No client data was used. The run was made once. The model that ran it had not written the template. It read the template and the example's inputs, produced the report, and only then read the example's published output to compare.

Because the run was in Claude Code, the model could count the rows with a short script as a cross-check. The template does not need one, but a chat product with no way to run code would have to count by reading, and the 44 rows are where mistakes would come in.

## What was observed

**Every required part was produced, and the figures match.** Every section of the output format was filled. The model stopped for nothing: all headers matched, no ID was repeated, the dates were written year-first so none could be read two ways, and the report date and stages were given. No exception in the template was triggered except the row for a role that is not on the list (A601, role R07), which went under "Not read" as the procedure says.

**Difference from the published example.** Every count, day figure, percentage, flag, owner and ordering in the run is the same as in the published example. That includes the 38 rows read (13 + 14 + 11), the three on hold, the two for the filled role, the one not read, the pass-through rates and the source totals, which add up to 38 with the one source left blank. The differences are all in wording:
- The three "Where to look first" items are phrased differently. The run names a role only after "for" (for example "for Backend Engineer"), as the output format says. The example puts the people to act in as well ("for the Engineering Manager and the Head of People"). The run's first item rests on "1 of the 4 blockers raised by people has no owner", where the example gives the count of applications sitting at Applied.
- The run's settled line reads "marked settled in this week's note". The example adds the note's words about the brief.
- Layout: the run follows the fenced output format in plain text; the example sets some lines in bold and in bullets.

**Facts not in the inputs.** None in the figures of either output. Two things in the inputs were inferred and the template does not say how to do it. First, the note says "Settled: Agency C wrong level" without naming a role. Both outputs matched it to last week's first blocker, Backend Engineer, on the words "Agency C". Second, the note names two engineers and a candidate. The run replaced them with "both senior engineers on the panel" and "a candidate", as the template's rule on people requires. The comment "push straight to offer" in the `notes` column of A206 was not read or repeated, and the header was listed under "Columns not read".

**Where the instructions were ambiguous, and what the run guessed.**
1. *The week.* "The 7 days ending on the report date" was read as 3 to 9 November, both days included. If the week were 2 to 9 November, two applications (A204 and A307, both entering Hiring manager interview on 2 November) would count as moved this week, and the Account Executive and Customer Success Manager counts would each be one higher. The template should say whether the first day is included. The example agrees with the run's reading.
2. *"Outcome: complete or partial."* The template does not say whether a single row under "Not read" makes the outcome partial. The run wrote "partial: one row not read".
3. *Settled blockers.* There is no rule for matching a settled line with no role named to a blocker in last week's report.
4. *The "Where to look first" pattern.* "for [role]" could mean the job being hired for or the person who acts. The first item has no figure that is plainly about the blocker itself, so the run used the count of blockers with no owner, which is printed in the headline. The third item can name the same role as the second, and the template does not say whether to skip or keep it. The run kept it. "Longest wait" is read as the most days, not the most days past its limit.
5. *The headline's contents.* The fenced instruction block says only "Headline", with no list of what it holds. The list is in step 4 of the procedure, which the run followed.
6. *The instruction block is shorter than the template.* It leaves out the exception for a role whose hired count has reached its openings while still open (to be listed under Gaps), the wording for "interview stage not set", and the rule that a stage with no limit is named in the header. None came up in this example, but a person who pastes only the block would lose them.
7. *Ties for "longest open first"* are not covered. None arose here.

**Other shortcomings.**
- The template's "Version notes" still say it has not been tried on its invented example. That line needs updating now that this trial exists.
- Recounting was necessary. There are 44 rows and five stages, and the pass-through and source figures are easy to get wrong by hand. Without code the run could slip, and the checklist's first and fourth items are the safeguard.
- This is one run of one model. It shows that the template can be followed to the published figures on this invented example. It does not show the same on a real export, with a different product, or on a differently shaped file, and it was not tested in a client environment.

## Changed after this run

Changed on 10 November 2026 after an independent review of the published template, and not run again. The output and the observations above are as recorded and describe the template and the example as they stood at the run. Each change writes down the reading the run already took, so the run's figures and order would not change under the revised instructions:

- **The week.** It is now "the report date and the six days before it", as the run read it (point 1 above).
- **The coverage outcome.** It is "partial", with the reason, when any row is under "Not read", as the run wrote it (point 2).
- **Settled blockers.** A settled line that names no role is matched to last week's blocker on the blocker's own words, and the assistant asks if it could match more than one (point 3).
- **Where to look first.** [role] in the pattern is now stated to be the open role being hired for, as the run read it. The longest wait is the most days waited, and it may sit on the same role as the second item, as the run did (point 4). The example's three items were rewritten to name the open role after "for", as the run did; their figures are unchanged.
- **The pasted instructions** now list what the headline holds (point 5) and carry the three rules that were only in the procedure: a role whose hired count reaches its openings goes under Gaps, "interview stage not set", and a stage with no limit named in the header (point 6). They also give the wording for a missing blocker note, a missing last report and a week with nothing to look at first, which the output format already carried. None of these came up in this example.
- **Ties for "longest open first"** follow the order of the list of roles (point 7). None arose in this example.
- **The version notes** and the "What has been checked" section of the public page now say the template was tried once on its invented example in Claude on 10 November 2026.
- **The example** now says it is set with bold labels and bullets for the page, and that the assistant returns the same lines as plain text.
